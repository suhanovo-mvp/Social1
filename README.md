# Social1

Управленческая платформа системных инноваций ДТСЗН — цифровая реализация экосистемы
ускоренного выявления, разработки, тестирования и внедрения инициатив сотрудников
учреждений Департамента труда и социальной защиты населения.

Конечный продукт платформы — не база предложений, а поток реально внедрённых
улучшений социальных услуг и административных процессов.

## Запуск

Требуется Node.js версии 22.5 или новее. Внешних зависимостей нет — платформа
использует встроенные модули Node.js, включая `node:sqlite`.

```bash
npm run seed
```

```bash
npm start
```

Портал открывается по адресу `http://127.0.0.1:3000`.

Порт и адрес меняются переменными окружения `PORT` и `HOST`.
Полная перезагрузка демонстрационных данных — `npm run reset`.

## Жизненный цикл инициативы

Управление построено по модели Stage-Gate: работы отделены от принятия решений.
Каждый этап завершается формальной точкой, где уполномоченный участник на основе
доказательств принимает решение **Go**, **Kill**, **Hold** или **Redirect**.
Каждое решение фиксируется с обязательной аргументацией — это формирует архив
знаний для будущих инициатив.

| Этап ТЗ | Стадия в системе | Gate | Кто решает | SLA |
|---|---|---|---|---|
| 1. Фиксация проблемы | Фиксация проблемы | — | автоматический переход | — |
| 2. Оценка и экспертиза | Оценка руководителем | Gate 1 | Руководитель учреждения | 3 рабочих дня |
| 2. Оценка и экспертиза | Экспертиза ДТСЗН | Gate 2 | Комитет экспертов ДТСЗН | 5 рабочих дней |
| 3. Разработка прототипа | Разработка MVP | Gate 3 | Команда разработки | 4 спринта по 2 недели |
| 4. Пилотирование | Пилотирование | Gate 4 | Координатор пилотов | 1 месяц + 1 неделя анализа |
| 5. Масштабирование | Масштабирование | Gate 5 | ДТСЗН | начало в течение 2 недель |

Этап 2 по ТЗ содержит две последовательные точки принятия решений, поэтому в
конвейере он представлен двумя стадиями. Соответствие этапам ТЗ показано в
интерфейсе на каждой карточке.

Сроки, критерии Gate, ответственные роли и перечень допустимых решений
настраиваются в разделе «Настройки платформы» без изменения кода.

## Функциональные модули

**Доска идей.** Витрина всех инициатив карточками с голосованием: сотрудник
поддерживает то, с чем сталкивается сам, и снимает голос повторным кликом.
Публичный статус — «На рассмотрении», «В разработке», «Пилотируется», «Готовится
к тиражированию», «Внедрено» — показывает продвижение идеи без погружения в
методологию Stage-Gate. Сортировки: популярные, набирающие поддержку, новые,
обсуждаемые. Поддержка коллег видна экспертам при оценке приоритета и учитывается
в прогнозе успеха, но не заменяет решение на Gate.

**Управление инициативами.** Стандартизированная форма подачи, уникальный номер,
страница полного жизненного цикла со всеми решениями и комментариями, поиск и
фильтрация по статусу, этапу, направлению и учреждению. Подписка на инициативу
включает уведомления о каждом её шаге.

**Движок бизнес-процессов.** Автоматическая маршрутизация между участниками,
создание задач в личных кабинетах, уведомления, таймеры SLA с предупреждением о
риске превышения и автоматической эскалацией просроченных решений координатору.

**Управление проектами.** Agile-доски со спринтами и бэклогом продукта,
перетаскивание задач между колонками, оценки в story points, хранилище
технической документации.

**Пилотирование.** Заявки учреждений на роль площадки, ведение пилота, мониторинг
KPI с базовым, целевым и фактическим значением, встроенные опросы сотрудников и
граждан.

**Аналитика и КПЭ.** Три группы показателей из ТЗ: вовлечённость и культура;
скорость и эффективность; качество и риски. Воронка Stage-Gate, динамика подачи и
внедрения, сравнение учреждений, выгрузка отчёта в CSV.

**Сообщество.** Тематические обсуждения, профили участников с вкладом и
признанием, библиотека лучших практик с материалами для самостоятельного
внедрения другими учреждениями.

**Администрирование.** Настройка конвейера, управление участниками и
организациями, журнал аудита, контроль SLA, состояние системы.

**Схемы процессов.** Отдельный раздел с детализированными моделями в нотации BPMN —
четырнадцать схем: по одной-трём на каждую роль плюс сквозной процесс от проблемы
до масштабирования. На схемах видны дорожки ответственности, потоки управления и
сообщений, точки принятия решений со всеми ветвями и сроки по SLA. Любую схему
можно разобрать по шагам: подсказки подсвечивают элементы прямо на диаграмме и
объясняют, что происходит на каждом шаге и почему именно так.

Разделы и шаги пронумерованы сквозным образом: схема — это раздел с номером от 1
до 14, каждый её элемент — шаг вида «4.6». Номер виден на самой фигуре, в перечне
схем, в разборе и в выгруженном PDF, поэтому на конкретный шаг можно сослаться
в регламенте.

**Выгрузка в PDF.** Схема выгружается векторным PDF: текст в файле ищется и
копируется, нумерация сохраняется. Под схемой печатается пошаговое описание
процесса — то же, что показывает разбор на экране: номер шага, его название и
пояснение, разложенные по колонкам. Формат листа подбирается по размеру схемы —
A3 для большинства, A2 для сквозного процесса. Альбом всех схем собирается одним
файлом с титульным листом и содержанием, сгруппированным по владельцам процессов.
PDF формируется на сервере без внешних библиотек: шрифт PT Sans встраивается
как CIDFontType2, поэтому кириллица отображается и ищется корректно.

| Роль | Схемы |
|---|---|
| Сквозной процесс | Полный цикл: от проблемы до масштабирования |
| Сотрудник учреждения | Подача инициативы · Участие в пилоте и обратная связь |
| Руководитель учреждения | Решение на Gate 1 · Заявка на пилотную площадку · Внедрение практики из библиотеки |
| Эксперт ДТСЗН | Экспертиза на Gate 2 · Публикация лучшей практики |
| Команда разработки и ЦТ | Разработка прототипа и Gate 3 |
| Поставщик технологий | Участие поставщика в проекте |
| Координатор пилотов | Организация пилота и Gate 4 |
| ДТСЗН | Масштабирование · Контроль SLA и эскалация · Настройка процесса |

**Интерактивное обучение.** Кнопка со знаком вопроса в шапке открывает каталог
обучающих сценариев. Каждый ведёт по интерфейсу с подсветкой элементов и
пошаговыми подсказками, при необходимости сам переходит между разделами.
Сценарии подбираются под роль участника:

| Сценарий | Шагов | Кому доступен |
|---|---|---|
| Знакомство с порталом | 7 | всем ролям |
| Доска идей и голосование | 5 | всем ролям |
| Как подать инициативу | 6 | сотрудник, руководитель, эксперт, ДТСЗН |
| Принятие решения на Gate | 5 | все, кто принимает решения на точках |
| Аналитика и КПЭ | 5 | руководитель, эксперт, координатор, ДТСЗН |
| Настройка процесса | 4 | ДТСЗН |

Обучение прерывается клавишей Esc и возобновляется позже; пройденные сценарии
отмечаются. При первом входе портал сам предлагает начать со знакомства.

Разбор схемы процесса — тот же движок подсказок, но сценарий собирается на лету из
данных диаграммы: 63 шага по четырнадцати схемам. Обучение по схеме объясняет
модель процесса, обучение по интерфейсу — где выполнять эти шаги в портале.

## Система метрик

**Группа 1 — процесс, вовлечённость, культура.** Количество зарегистрированных и
внедрённых инициатив, прохождение каждого Gate, уровень вовлечённости сотрудников,
вовлечённость в голосование и лидеры поддержки, участники пилотов, доля
масштабирования «снизу», валоризация эффекта.

**Группа 2 — эффективность и скорость.** Скорость полного цикла «проблема →
масштабирование» (среднее и медиана), время прохождения каждого этапа в сравнении
со стандартом обслуживания, коэффициент успешности пилотирования, время до первого
решения.

**Группа 3 — качество и риски.** Количество решений Kill, Redirect и Hold, риск
«заморозки» инициатив, распределение остановок по этапам. Решения Kill не являются
негативным показателем: они означают, что система отсеивает нежизнеспособные
проекты и экономит ресурсы.

## Роль искусственного интеллекта

ИИ поддерживает человека, но не принимает решения на Gate. Все алгоритмы
объяснимые: система показывает не только результат, но и факторы, которые к нему
привели.

- **Классификация инициатив** по тематическим направлениям с указанием признаков,
  по которым сделан вывод.
- **Поиск похожих инициатив** при подаче — предотвращает дублирование усилий.
- **Анализ обратной связи** пилотов: тональность, ключевые темы, проблемные сигналы.
- **Прогноз успеха** с раскрытием каждого фактора и его вклада в оценку —
  включая поддержку коллег как независимый сигнал востребованности решения.

## Безопасность

- Пароли хранятся в виде scrypt-хэшей с индивидуальной солью.
- Сессии в HttpOnly-cookie с флагом SameSite=Strict.
- Ролевая модель доступа проверяется на сервере при каждом запросе; права
  интерфейса носят вспомогательный характер.
- Журнал аудита неизменяем: записи связаны цепочкой SHA-256, изменение или
  удаление задним числом ломает цепочку и выявляется проверкой целостности.
  Защита продублирована триггерами базы данных.
- Заголовки безопасности, включая строгую политику Content-Security-Policy.

  js/core.js     HTTP-клиент, состояние, маршрутизация, форматирование, диаграммы

Платформа спроектирована с учётом будущего расширения: слой API отделён от
интерфейса, модули независимы, конфигурация процесса вынесена в данные.
Открытые REST-эндпоинты позволяют интегрировать платформу с кадровыми системами
и порталами государственных услуг без изменения ядра.

## Сторонние материалы

Шрифт PT Sans (ParaType) распространяется по лицензии SIL Open Font License 1.1;
текст лицензии — в `assets/fonts/OFL.txt`. Шрифт используется только для выгрузки
схем в PDF. Других сторонних материалов и npm-зависимостей в проекте нет.

## Ограничения демонстрационной версии

- Хранилище — SQLite в файле `data/social1.db`; для промышленной эксплуатации
  требуется СУБД с репликацией и шифрованием на уровне хранения.
- Интеграции с внешними системами ДТСЗН не реализованы — по ТЗ на данном этапе
  они не требуются.
- Уведомления доставляются внутри платформы; электронная почта и SMS не подключены.
- Загрузка файлов ограничена ссылками на материалы.
